# Vault42 Documentation

Every published document in this directory, with what it is for and when to read it.
Adding a document means adding a row here.

## Start here

| Document | What it covers |
|---|---|
| [Specification](spec.md) | The authoritative description of what Vault42 is and does, verified against the implementation. Read this first if you are evaluating the project. |

| [Configuration Reference](config.md) | Every environment variable, the four deployment profiles, the `_FILE` secret convention, and the fail-closed overrides an auditor will ask about. |

## Operating it

| Document | What it covers |

## Security and compliance

| Document | What it covers |
|---|---|
| [Security Decisions & Accepted Risks](security.md) | The engineering accepted-risk log, AR-1 through AR-18: what Vault42 deliberately does not defend against, and why. The compliance register numbers its own risks CR-nn; the two namespaces are disjoint. Read this before deploying. |
| [Attack Cheatsheet](cheatsheet.md) | Concrete attack vectors against JWT, sessions, crypto, OAuth2, the KMS unwrap oracle and the deployment surface, each mapped to the defence and the test that proves it. |
| [Standards Compliance](COMPLIANCE.md) | Mapping to NIST SP 800-63B, OWASP ASVS, OWASP Top 10 and the RFC family, with the tests that back each claim. |
| [OpenSSF Best Practices answers](openssf-best-practices.md) | Every passing-level criterion answered against the evidence in this tree, prepared so the badge needs only a registration. Tracked as CR-35. |
| [Privacy & Data Protection Policy](PRIVACY.md) | GDPR posture: lawful basis, data inventory, retention, data-subject rights, processors, and the breach-notification procedure. |

Vulnerability reports go to **<vault@42-v.com>**, never to a public issue. See
[SECURITY.md](../SECURITY.md) for the intake process, the security-release process, and the
support and versioning policy. Contributors should read
[CONTRIBUTING.md](../CONTRIBUTING.md) before opening a pull request.

## Not published

Some documents referenced in commit messages and code comments are kept on disk but excluded
from the repository by `.gitignore`: internal working notes, the spec draft, dated security
audits and the security review. They are not available on GitHub. No document in this directory
should link to one; if you find a link that does, it is a bug.
